# Do AI watermarks survive contact with the real world?

**Preliminary findings for the Ohio House Technology and Innovation Committee**
Prepared by student volunteers for the office of Rep. Christine Cockley (D-06)
regarding HB 813 (ORC 1349.12–1349.16, proposed)

> **Status: preliminary.** The harness is complete and the local transform arm
> has run. The platform arm has not: no social platform has been tested yet, and
> the corpus currently holds three public fixture images, only one of which
> carries a valid signature. Every number below carries its sample size. Nothing
> here should be quoted in committee until Sections 3 and 4 are filled in.
>
> Generated tables and figures live in `results/tables.md`. Every claim in this
> memo cites a row in `data/results/runs.csv` or a published source.

## 1. What we tested and what we found

HB 813 would require AI-generated products to carry a watermark, enforced by the
Attorney General. The technical question the bill depends on is whether such a
mark is still there when someone looks for it. We are measuring that.

We test the strongest mark currently deployed: a **C2PA manifest**, the
cryptographically signed provenance record that Adobe, Leica, and others attach
at the moment of creation. If C2PA does not survive, nothing weaker will.

**What we can already say, and it is not a matter of sample size:**

Re-encoding an image destroys the manifest. Every transformation we tested that
touches the pixels — saving at a different quality, resizing, cropping,
rotating, converting between formats, screenshotting — returned `absent`, no
manifest at all. This is not a close call or a statistical tendency. The
manifest lives in a container segment beside the image data, and ordinary
encoders do not copy that segment forward. There is nothing probabilistic about
it.

The one transformation that *preserved* the manifest was deleting the EXIF block
without re-encoding — the "remove properties before sharing" feature people are
told to use for privacy. It leaves the signature intact, because it never
rebuilds the file.

**The shape of the problem for a mandate:** the mark is destroyed by the most
ordinary handling imaginable and preserved by the one operation a person
performs *deliberately* to remove metadata. That is close to the opposite of
what a watermarking requirement assumes.

**What we cannot yet say.** Whether platforms strip the mark on upload is the
question that determines whether the bill is enforceable for the images most
Ohioans actually see, and we have not measured it yet. It is Section 3, and it
is the study's core exhibit. See Section 7 for the schedule.

## 2. Survival by transform

Current run: **1 signed source image × 19 transformations and two-step chains.**
n = 1 per row. This establishes the mechanism, not the rate; the rate needs the
full 40–60 image corpus.

See `results/tables.md` and `results/figures/survival_by_transform.png` for the
generated table and figure, regenerated by `make report`.

Summary of the current run:

| Transformation | Manifest survived |
|---|---|
| EXIF block removed in place (no re-encode) | yes |
| Re-saved as JPEG (quality 95, 75, 50) | no |
| Resized (75%, 50%, 25%) | no |
| Cropped (5%, 10%, 25% border) | no |
| Rotated (90°, 180°) | no |
| PNG → JPEG → PNG conversion | no |
| Screenshotted | no |
| Opened in an editor and saved | no |
| Screenshot then recompressed *(realistic worst case)* | no |

**Note on quality 95.** Re-saving at near-original quality — a change a person
cannot see — destroys the manifest as completely as resizing to a quarter. The
mark is not degraded by handling; it is absent or present, and re-encoding makes
it absent.

**Note on the three-valued outcome.** We distinguish a manifest that is *gone*
from one that is *present but no longer verifies*. Locally we only ever produced
the first. The second matters for the platform arm: a platform that preserves
the container while re-encoding the pixels produces an image that still carries
a claim, and the claim no longer checks out. For an enforcement agency those are
different situations, and a statute that treats them identically loses the
distinction between "nobody vouched for this" and "somebody vouched for this and
then it changed."

## 3. Survival by platform — **NOT YET MEASURED**

This is the section that decides whether the bill's mechanism reaches the images
Ohioans actually encounter, because almost nobody views an image as the file
that left the generator. They view it after a platform has processed it.

Protocol is written (`docs/PLATFORM-PROTOCOL.md`), the logging harness works,
and the platform list is set: Facebook, Instagram, X, Reddit, LinkedIn, Discord,
WhatsApp, iMessage, SMS/MMS, Gmail attachment, Google Drive.

Uploads are performed by hand. Automating them would violate platform terms of
service, and a bot's upload is not the behavior we are trying to characterize.

## 4. Text watermarking — **NOT YET MEASURED**, and coverage will be limited

Be upfront about this in committee.

Most production text watermarking systems, including Google's SynthID-Text, ship
no public detector. We cannot measure them, and neither can anyone outside the
vendor. What we can measure is the open green-list scheme from Kirchenbauer et
al. against a model we run locally, degraded by paraphrase, round-trip
translation, synonym substitution, truncation, and interleaving human sentences.

That produces a **lower bound on fragility for one open scheme**, not a claim
about any vendor's system. We will say so in exactly those words.

The coverage gap is itself a policy-relevant fact, and it belongs in the memo
rather than in a footnote: **a mark the Attorney General has no way to verify is
a mark the Attorney General has no way to enforce.** If a statute requires text
watermarking, the question of who can check compliance, with what tool, has to
have an answer.

## 5. How other jurisdictions handled downstream stripping — **IN PROGRESS**

Scaffold and method in `policy/state-comparison.md`. Comparison set: California
SB 942, Colorado SB 24-205, Utah SB 149, EU AI Act Article 50, China's deep
synthesis labeling provisions, and HB 813 as introduced.

The column that matters is **who bears the obligation**. Our local results
already show a mark applied at generation does not survive the file being
re-saved. If the duty sits on the generator alone, a compliant generator marks
the image, the next handler re-encodes it, the mark is gone, and every party has
complied while the goal has failed.

Cells stay empty until someone has read the statutory text. Summarizing other
states' law from memory would put unverified claims about the law in front of a
legislator.

## 6. Questions HB 813 may want to answer

Open questions raised by the measurements, not recommendations. The office
decides what to do with them.

1. **Where does the duty attach?** If it attaches at generation, our results
   suggest the mark will usually be gone by the time anyone looks. Is there an
   intended duty on anyone downstream — a platform, a distributor, an editing
   tool — to preserve a mark it receives?

2. **What counts as compliance when the mark is destroyed by an ordinary save?**
   Re-encoding at visually identical quality removes the manifest. Is a
   generator that marked correctly still compliant once a user saves the file?
   Presumably yes — which then raises what the requirement accomplishes.

3. **Is a broken mark treated differently from a missing one?** The statute as
   introduced does not appear to distinguish them. They are technically distinct
   and, for an enforcement agency, evidentially distinct.

4. **Does "watermark" mean a visible overlay, embedded metadata, a
   cryptographic manifest, or a signal in the pixels themselves?** These have
   very different survival characteristics. A visible overlay survives
   re-encoding and is trivially cropped out; a manifest is the reverse. The
   choice determines what the mandate actually does.

5. **Who verifies, and with what?** Enforcement runs through the Attorney
   General. For C2PA there is a public verifier. For most text watermarking
   there is none, and for pixel-domain watermarks the detector is usually the
   vendor's private property. What tool is the AG's office expected to use?

6. **Does provenance stored on a vendor's server count?** Some images carry no
   embedded mark at all, only a URL pointing at a manifest the vendor holds. We
   found one in a three-image sample. That provenance disappears when the vendor
   does.

## 7. Method and reproduction

Everything is reproducible from a clean clone.

```bash
uv sync
uv run python -m src.corpus fetch    # or `scan` after adding your own images
uv run python -m src.sweep
uv run python -m src.report
uv run pytest
```

- **Detection** uses the C2PA reference library (`c2pa-python`, c2pa-rs
  0.90.15), offline: we never fetch a remote manifest, so results do not depend
  on a third party's uptime.
- **Outcomes** are three-valued (`present_valid`, `present_invalid`, `absent`)
  and recorded per experiment in `data/results/runs.csv` with a run ID,
  timestamp, source SHA-256, transform chain, and result hash. Nothing
  hand-edits that file.
- **Transformations** are named for the human behavior they stand in for and
  none of them takes a detector's output as input. This harness measures
  fragility; it is not a removal tool and is not structured as one.
- **Images** are content-addressed. `data/corpus/manifest.json` is committed;
  the images are not, for licensing reasons.

### Known limitations

- **Sample size.** One signed image so far. The mechanism is established; rates
  are not.
- **Screenshots are simulated**, not captured from a physical screen: the
  decoded pixels are composited onto a fresh canvas and re-encoded, which is
  what a screen capture produces. It does not model display scaling or a photo
  taken of a screen.
- **HEIC is untested.** It needs an additional decoder, and iPhone-native
  formats are a real-world path worth covering.
- **No video or audio.** HB 813's reach is broader than still images.
- **Platform behavior changes without notice.** Every row is timestamped for
  that reason. A platform result is a result as of that date.
